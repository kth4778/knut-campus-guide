# E2E 테스트 계획

> 상태: **61개 모두 구현·통과** (2026-11-18, 건물 지도 D10~D12 추가) · 코드: `tests/e2e/` · 설정: `playwright.config.js`

Playwright로 실제 브라우저를 띄워 사용자처럼 눌러 보는 테스트 **57개**를 만들고,
main에 push할 때마다 자동으로 돌려 **하나라도 실패하면 배포를 막는다.**
외부 서비스(버스 API·챗봇 AI·지도 서버)는 가짜 응답으로 바꿔 언제 돌려도 결과가 같게 한다.

```
E2E 테스트
├─ 도구: Playwright (Chromium, 휴대폰 화면 흉내 포함)
├─ 화면 크기 2개: 컴퓨터 폰 틀(1440×900) · 휴대폰(390×844)
├─ 외부 서비스는 가짜 응답으로 대체
├─ 테스트 묶음 12개 · 57개 (P0 19 · P1 30 · P2 8)
└─ GitHub Actions: push마다 실행 → 실패하면 배포 중단
```

## 1. 왜 필요한가

팀원 여럿이 PR 없이 main에 바로 올리고, 올리는 순간 실제 사이트가 바뀐다.

- 2026-11-17에만 「지도 위에서 하단 탭이 안 눌림」, 「버스 키가 빈 채로 배포」,
  「아래 창이 폰 밖으로 삐져나옴」이 올라간 뒤에야 발견됐다.
- `app.js` 하나를 여러 명이 고치므로 남의 기능을 모르고 깨뜨리기 쉽다.

## 2. 구성

| 구성 | 내용 |
|---|---|
| 도구 | Playwright. 저장소에 `package.json`과 `tests/e2e/`를 새로 만든다 |
| 서버 | 테스트 중 `dist/`를 `localhost:5178`로 띄운다 (네이버 지도 등록 주소) |
| 화면 크기 | `desktop`: 폰 틀 1440×900 / `mobile`: 390×844, 터치 |
| 매 테스트 시작 | localStorage를 비워 좋아요·저장·게시물이 남지 않게 한다 |
| 가짜 응답 | 버스 API → 미리 저장한 정상 응답 파일 / 챗봇 AI(Ollama) → 정해진 답 / 공유·클립보드 → 무엇을 보냈는지 기록만 |
| 네이버 지도 | 두 경우 모두 시험: 네이버가 뜰 때 / 네이버 주소를 막았을 때 Leaflet으로 바뀌는지 |

## 3. 어려운 점과 대응

- **외부 서비스는 매번 결과가 다르다.** 버스 도착은 시간대에 따라 0건일 수 있고, Ollama는 CI 컴퓨터에 없다.
  → 진짜 호출은 막고 가짜 응답을 준다. 진짜 버스 키가 살아 있는지는 하루 1번 도는 테스트(E5) 하나만 둔다.
- **지도는 캔버스라 그림을 직접 확인하기 어렵다.** → 핀은 HTML 요소(`.marker`)로 확인하고, 지도 그림 자체는 비교하지 않는다.
- **홈 피드 순서가 날짜마다 바뀐다.** → 테스트에서 브라우저 시계를 고정한다.
- **다국어는 화면 글자를 나중에 바꿔 끼운다.** → 바뀐 뒤를 기다렸다가 확인한다.

## 7. 실행 방법

```bash
npm ci                                   # 처음 한 번
npx playwright test --project=desktop --project=mobile   # 로컬 56개
npm run test:p0                          # 배포를 막는 P0 만 (push 전에)
npx playwright test --project=deploy     # 배포된 공개 사이트 확인
```

- 테스트 중 `dist/` 를 `localhost:5178` 로 띄운다(이미 떠 있으면 그대로 씀).
- 화면 사진 비교(J4) 기준은 `tests/e2e/look.spec.js-snapshots/` 에 있고, 디자인을 일부러 바꿨으면 `npx playwright test -g J4 --update-snapshots` 로 새로 찍는다. CI(리눅스)에서는 글꼴이 달라 건너뛴다.
- GitHub Actions(`pages.yml`): push → **테스트(56개) → 통과하면 배포 → 배포 확인(5개)**. 테스트가 하나라도 실패하면 배포하지 않는다.
